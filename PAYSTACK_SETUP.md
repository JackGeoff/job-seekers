# Paystack Setup

Paystack integration is configured through Laravel services config. Never commit `.env` or send keys through chat. The repository's `.gitignore` already excludes `.env`.

## Environment

Add these lines to the local `.env` and later the cPanel production environment. Enter the keys locally; do not put their values in source files.

```dotenv
PAYSTACK_PUBLIC_KEY=pk_test_a61456787bfd100c8c65e64ab7f54b73defc654b
PAYSTACK_SECRET_KEY=sk_test_3745c4f639b3ed02c53f2a5961e5f35e87de09a0
PAYSTACK_PAYMENT_URL=https://api.paystack.co
PAYSTACK_CURRENCY=KES
PAYSTACK_WEBHOOK_SECRET=
```

Paystack's official webhook signature uses the integration secret key. Unless Paystack has provided a distinct webhook signing secret for your account, set `PAYSTACK_WEBHOOK_SECRET` to the same value as `PAYSTACK_SECRET_KEY`. The application falls back to the secret key if the webhook secret is empty.

## Local Setup

1. Add your Paystack **test** keys to `.env`.
2. Apply the additive migrations with an available terminal/Artisan runner:

   ```sh
   php artisan migrate --force
   ```

   The migrations add Paystack transaction state to the existing `employer_payment_orders` table. They do not change existing subscription records.
3. Clear configuration/route/view caches after changing environment values:

   ```sh
   php artisan optimize:clear
   ```
4. Test card checkout. The application initializes a KES transaction using the pending order's server-side amount, then redirects to Paystack Checkout. The callback verifies the reference server-to-server; it never trusts the browser query string as proof of payment.
5. Test M-Pesa with a Kenyan test number supported by your Paystack test account. The app sends a Charge API request with `mobile_money.provider=mpesa`, normalized `+254` phone number, KES amount in cents, and a unique reference. Paystack returns `pay_offline` and display text while waiting for phone authorization.
6. A pending order never grants credits. Only a successful server-side transaction verification creates a subscription.

Official references:
- [Transaction initialize and verify](https://paystack.com/docs/api/transaction/)
- [Charge API](https://paystack.com/docs/api/charge/)
- [Mobile money and M-Pesa](https://paystack.com/docs/payments/payment-channels/#mobile-money)
- [Webhooks](https://paystack.com/docs/payments/webhooks/)

## M-Pesa Availability

Paystack documents M-Pesa for Kenya through the Charge API (`/charge`) using the `mobile_money` object. Test-mode credentials or account settings may not have this channel enabled. If Paystack rejects the request, the order remains pending and the employer can retry; no payment or subscription is simulated. Ask Paystack support to enable Kenya M-Pesa test charges for your integration if needed.

## cPanel Deployment

1. Back up the application files and database.
2. Upload the changed PHP, Blade, JavaScript, config, documentation, and migration files from this change. Upload the rebuilt `public/build/manifest.json` and all assets referenced by it.
3. Add the Paystack environment values in cPanel's environment editor or the application's server-side `.env`. Do not upload `.env` into a public directory or commit it.
4. Run `php artisan migrate --force` with cPanel Terminal/Artisan tooling or ask the host to run it. The new migrations are:
   - `2026_10_02_000002_add_paystack_fields_to_employer_payment_orders_table`
5. Run `php artisan optimize:clear`, then restart PHP/OPcache if the host retains old code/config.
6. Test a small test-mode card transaction, verify the pending order changes to paid only after Paystack verification, and confirm one subscription is created.

## Webhook Setup

In the Paystack Dashboard, configure this production webhook URL:

```text
https://jobseekers.co.ke/paystack/webhook
```

The callback URL is generated by Laravel as `/paystack/callback`; it is for the authenticated browser return. Webhook processing is independent and remains the reliable confirmation path. The webhook route is public but validates `x-paystack-signature` against the exact raw request body before handling events. No global CSRF exemption is added.

Paystack cannot call localhost. For temporary local webhook testing, use a temporary HTTPS tunnel such as ngrok or Cloudflare Tunnel and configure its HTTPS URL ending in `/paystack/webhook` in the **test-mode** Paystack Dashboard. Forward the tunnel to the local Laravel port, test only with test keys, then remove the temporary webhook URL and stop the tunnel. Never point live Paystack events at an untrusted or temporary endpoint.

## Payment and Subscription Behavior

A paid renewal/upgrade creates a new subscription row; existing subscriptions are not modified or deleted. The application continues selecting the active successful subscription with the latest expiry, matching the existing behavior. Repeated callbacks/webhooks are idempotent: the order row is locked, the stored Paystack reference and payment details are checked, and an already-paid order does not create a second subscription.

For troubleshooting, correlate the internal order UUID shown to the employer with the stored Paystack reference. Logs contain order/reference identifiers and error categories only, never secret keys or authorization headers.
